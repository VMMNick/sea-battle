# Морський бій онлайн

Проста онлайн-гра "Морський бій" для двох гравців у реальному часі (WebSocket, без бази даних).

## Як грати

1. Один гравець відкриває сайт і тисне **«Створити нову гру»** — отримує код кімнати (4 символи).
2. Другий гравець відкриває той самий сайт, вводить код і тисне **«Приєднатися»**. Або обидва тиснуть **«⚡ Швидка гра»** — сервер миттєво паруватиме їх, щойно обоє шукатимуть суперника, без обміну кодами.
3. Обидва розставляють кораблі (клік — поставити, `R` або кнопка — обертати, є кнопка «Випадково»).
4. Бій: по черзі стріляєте по клітинках суперника. Влучання дає ще один постріл (класичне правило).
5. Перемагає той, хто першим потопить весь флот суперника.

Перемоги в іграх проти інших гравців (не проти бота) враховуються в загальній таблиці лідерів — кнопка **🏆** у шапці сторінки. Щоб зʼявитися там під власним іменем, встановіть нікнейм у налаштуваннях (**⚙️**).

Під час бою проти іншого гравця (не бота) доступний невеликий чат і швидкі emoji-реакції — під історією пострілів.

Набір кораблів класичний: 1×4-палубний, 2×3-палубні, 3×2-палубні, 4×1-палубні. Кораблі не можуть торкатися один одного навіть по діагоналі — сервер це перевіряє.

Інтерфейс за замовчуванням українською; перемикач **UA/EN** — у налаштуваннях (**⚙️**). Вибір мови зберігається в браузері й одразу перекладає весь інтерфейс, включно з повідомленнями від сервера.

При першому візиті автоматично показується короткий вступний тур із поясненням основних дій; повторно відкрити його можна будь-коли кнопкою **❓** у шапці.

## Запуск локально

```
npm install
node server.js
```

Відкрити `http://localhost:8080` у двох вкладках (або надіслати посилання другу, якщо порт відкритий назовні).

Порт можна змінити змінною середовища `PORT`.

## Деплой в інтернет (щоб грати з будь-ким по посиланню)

Гра — це звичайний Node.js застосунок з постійним WebSocket-з'єднанням, тож підходить будь-який хостинг, що тримає процес живим (не «безсерверний»/serverless). Найпростіші безкоштовні варіанти:

### Render.com (рекомендовано, є готовий `render.yaml`)

1. Заливаєте цю папку в репозиторій на GitHub.
2. На render.com: New → Blueprint → вибираєте репозиторій. Render сам прочитає `render.yaml` і розгорне сервіс.
3. Через пару хвилин отримаєте публічний URL типу `https://sea-battle-xxxx.onrender.com`.

### Railway.app

1. Заливаєте папку в GitHub-репозиторій (або встановлюєте Railway CLI і робите `railway up` прямо з цієї папки).
2. New Project → Deploy from GitHub repo.
3. Railway сам визначить, що це Node.js застосунок (`npm start`), і видасть публічний домен.

### Fly.io / інші

Підійде будь-який хостинг з підтримкою постійних Node.js процесів і WebSocket (Fly.io, Cyclic, Glitch тощо) — застосунок не використовує жодних специфічних для платформи функцій.

## Структура проєкту

```
server.js               — WebSocket-сервер, вся ігрова логіка (кімнати, розстановка, хід, перемога)
public/index.html        — розмітка сторінки
public/style.css         — стилі
public/js/main.js        — точка входу: усі обробники подій DOM, обробка повідомлень сервера
public/js/state.js        — спільні константи та стан гри
public/js/dom.js          — DOM-хелпери, малювання силуетів кораблів, статус-бар, оголошення
public/js/storage.js      — localStorage: сесія, налаштування, статистика
public/js/sound.js        — синтезовані звукові ефекти та вібрація
public/js/network.js      — WebSocket-з'єднання
public/js/keyboard-nav.js — клавіатурна навігація по сітках
public/js/placement.js    — екран розстановки кораблів
public/js/battle.js       — екран бою: сітки, історія пострілів, анімації влучань
public/js/chat.js         — чат і emoji-реакції в бою проти іншого гравця
public/js/i18n.js         — словник uk/en, t(key, vars) і переклад статичної розмітки через data-i18n-*
test/simulate.js         — автотест: дві "гри" через WebSocket грають повну партію до перемоги
test/quick-match.js      — автотест: пара гравців у черзі швидкої гри паруються; скасування/розрив зʼєднання звільняють чергу
test/leaderboard.js      — автотест: перемоги в PvP-іграх коректно накопичуються в глобальній таблиці лідерів
test/chat.js             — автотест: чат і emoji-реакції (обрізання тексту, allow-list emoji, доставка обом сторонам)
test/e2e.js              — автотест інтерфейсу (Playwright): дві вкладки браузера грають через UI
test/e2e_chat.js         — автотест інтерфейсу (Playwright): чат і реакції в бою через UI
test/e2e_i18n.js         — автотест інтерфейсу (Playwright): перемикач мови UA/EN, переклад статики й динамічних рядків
test/e2e_onboarding.js   — автотест інтерфейсу (Playwright): вступний тур для нових гравців (показ, закриття, кнопка ❓, переклад)
test/run-all.js          — піднімає сервер і запускає всі тести з test/ одним прогоном (npm test)
```

## Тести

Найпростіше — одна команда, яка сама піднімає сервер на окремому порту і послідовно запускає всі тести з `test/`:

```
npm install
npx playwright install chromium   # один раз — потрібно для UI-тестів
npm test
```

Повний прогін займає кілька хвилин (частина тестів грає реальні партії проти бота до кінця). Наприкінці виводиться підсумкова таблиця pass/fail.

Кожен файл також можна запустити окремо, якщо потрібно налагодити конкретний сценарій:

```
node server.js &                 # підняти сервер
URL=ws://localhost:8080 node test/simulate.js   # серверна логіка
URL=http://localhost:8080 node test/e2e.js      # UI (потрібен playwright)
```

На кожен push/PR у GitHub тести автоматично запускаються через GitHub Actions (`.github/workflows/ci.yml`).
